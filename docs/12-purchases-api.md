# WIZANO | وزانو — المشتريات الآجلة (API)

| البند | القيمة |
|---|---|
| رقم الوثيقة | WZ-PUR-001 |
| الإصدار | 1.0 |
| المرحلة | المرحلة 8 — المشتريات الآجلة |
| المصدر | `server/src/modules/purchases/` |

---

## 1. المفهوم

- **عملية الشراء** (`purchases`) تسجّل توريدًا/بيعًا آجلًا لعميل داخل محل: نص الأصناف،
  الإجمالي، المدفوع وقت الشراء، والمتبقي المحسوب.
- **العميل إلزامي** ويجب أن يكون مرتبطًا فعليًا بالمحل (`customer_shop_links` بحالة `active`)؛
  وهو يحقق العزل (R-06) ومنع ربط عملية بعميل محل آخر.
- **المدفوع وقت الشراء** لا يُدمج في الإجمالي؛ يُسجَّل **دفعة مستقلة** (`payments`) مرتبطة
  بالعملية لمنع الحساب المزدوج ولتماسك كشف الحساب.
- **رقم العملية** (`shop_seq`) فريد ضمن المحل عبر عدّادات (`shop_counters`) بلا فجوات قدر الإمكان.
- **المتبقي** قيمة مشتقة تُخزَّن للاستعلام السريع، و**رصيد العميل بعد العملية** (`balance_after`)
  = Σ المشتريات − Σ المدفوعات (D-09، قابل لإعادة الحساب).

---

## 2. المسارات

كل المسارات تحتاج `Authorization: Bearer <access>` + انتماء فعّال للمحل (`requireShopMembership`).

| الطريقة | المسار | الحالة | الوصف |
|---|---|---|---|
| GET | `/api/v1/shops/:shopId/purchases?customerId=` | 200 | قائمة مشتريات المحل (اختياريًا لعميل) |
| POST | `/api/v1/shops/:shopId/purchases` | 201 | تسجيل عملية شراء (+ دفعة مرتبطة إن وُجد مدفوع) |
| GET | `/api/v1/shops/:shopId/purchases/:purchaseId` | 200 | تفاصيل عملية |

**الطلب (إنشاء):**

```jsonc
{
  "id": "uuid-v7-اختياري",       // معرّف ثابت من التطبيق (D-07) — يمنع التكرار
  "customerId": "uuid",          // إلزامي، عميل مرتبط بالمحل
  "itemsText": "أرز 10كجم...",   // إلزامي (حرف واحد على الأقل)
  "totalAmount": 10000,          // إلزامي، ≥ 0
  "paidAmount": 3000,            // اختياري (افتراضي 0)، ≥ 0 و ≤ totalAmount
  "notes": "...",                // اختياري
  "occurredAt": "2026-10-20T22:00:00.000Z" // اختياري (افتراضي: الآن)
}
```

- الترويسة `Idempotency-Key` اختيارية: عند إعادة الإرسال بنفس المفتاح تُعاد العملية القائمة بدل إنشاء نسخة (R-07).

**الاستجابة (عملية):**

```jsonc
{ "data": {
  "id": "uuid", "shopId": "uuid", "customerId": "uuid",
  "shopSeq": "1", "occurredAt": "...", "itemsText": "...",
  "totalAmount": "10000", "paidAmount": "3000", "remainingAmount": "7000",
  "notes": null, "status": "active", "statusReason": null,
  "balanceAfter": "7000", "createdAt": "...", "updatedAt": "..." } }
// القائمة
{ "data": { "items": [ { "...": "..." } ] } }
```

> **ملاحظة:** المبالغ تُعاد كسلاسل نصية (bigint) لتجنّب فقدان الدقة في JavaScript.

## 3. قواعد

- **العزل:** عدم الانتماء للمحل ⇒ 403 (رسالة موحّدة لا تكشف وجود المحل).
- عميل غير مرتبط بالمحل ⇒ 404 (لا نكشف وجوده)؛ نفس السلوك عند فلترة القائمة بعميل غير مرتبط.
- **القيود المالية:** `total ≥ 0`، `paid ≥ 0`، `paid ≤ total`، و`remaining = total − paid`
  (يُفرض على مستوى المدخلات وعلى قاعدة البيانات عبر CHECK).
- **الدفعة المرتبطة:** إن كان `paidAmount > 0` تُنشأ دفعة (`payments`) بـ`notes = "دفعة وقت الشراء"`
  و`shop_seq` مستقل (kind = payment) داخل نفس المعاملة.
- **منع التكرار:** (أ) نفس `id` من العميل ⇒ تُعاد العملية القائمة؛
  (ب) نفس `Idempotency-Key` ⇒ تُعاد العملية القائمة (مع تسجيل في `sync_operations`).
- **العدّادات:** `shop_counters(kind = purchase|payment)` تُزاد ذرّيًا داخل المعاملة.

---

## 4. الأخطاء

| الحالة | الكود | متى |
|---|---|---|
| 400 | `BAD_REQUEST` | فشل تحقق المدخلات (حقول ناقصة/سالبة/`paid > total`) |
| 401 | `UNAUTHORIZED` | لا رمز مصادقة |
| 403 | `FORBIDDEN` | لا انتماء للمحل |
| 404 | `NOT_FOUND` | العملية غير موجودة، أو العميل غير مرتبط بالمحل |

## 1. نموذج المصادقة (D-05)

- **الجلسة:** رمز وصول قصير العمر (`JWT`، HS256، افتراضيًا 15 دقيقة) + رمز تجديد طويل العمر (افتراضيًا 30 يومًا) **بتدوير**.
- **كلمة المرور:** تُجزَّأ بـ **argon2id** (~19MB, timeCost=2)؛ لا تُخزَّن خامًا ولا تُسجَّل ولا تُعاد في أي استجابة.
- **رمز التجديد:** سلسلة عشوائية 256-bit؛ يُخزَّن **SHA-256** منها فقط في جدول `refresh_tokens`.
- **التدوير وكشف السرقة:** عند التدوير يُبطَل الرمز القديم ويُصدر جديد في نفس `family_id`. إعادة استخدام رمز مُبطَل تُبطِل **السلسلة كاملة** (R-08).
- **الرسائل:** موحّدة عند فشل الدخول («البريد/الهاتف أو كلمة المرور غير صحيحة») لمنع تخمين وجود الحساب.

## 2. المسارات

| الطريقة | المسار | الحالة | الوصف |
|---|---|---|---|
| POST | `/api/v1/auth/register` | 201 | تسجيل مستخدم (اسم + بريد أو هاتف + كلمة مرور) → مستخدم + رمزان |
| POST | `/api/v1/auth/login` | 200 | دخول → مستخدم + رمزان |
| POST | `/api/v1/auth/refresh` | 200 | تدوير رمز التجديد → رمزان جديدان |
| POST | `/api/v1/auth/logout` | 204 | إبطال رمز التجديد |
| GET | `/api/v1/me` | 200 | المستخدم الحالي + انتماءاته بالمحلات (Bearer) |

**نماذج الطلب (مختصر):**

```jsonc
// register
{ "displayName": "اسم", "email": "a@b.com", "phone": "+9677...", "password": "******" }
// login
{ "email": "a@b.com", "password": "******" }   // أو phone بدل email
// refresh / logout
{ "refreshToken": "<raw>" }
```

**نماذج الاستجابة:**

```jsonc
// نجاح المصادقة
{ "data": { "user": { "id": "...", "displayName": "...", "email": "...", "phone": null, "status": "active", "createdAt": "..." },
            "tokens": { "accessToken": "...", "refreshToken": "...", "tokenType": "Bearer", "expiresIn": 900 } } }
// /me
{ "data": { "user": { ... }, "memberships": [ { "shopId": "...", "shopName": "...", "role": "owner", "permissionKeys": [] } ] } }
```

## 3. الأخطاء الموحّدة

الشكل: `{ "error": { "code", "message_ar", "details?" } }`.

| الحالة | الكود | متى |
|---|---|---|
| 400 | `BAD_REQUEST` | تحقق Zod فاشل (تفاصيل الحقول في `details`) |
| 401 | `UNAUTHORIZED` | ترويسة/رمز مفقود أو غير صالح، بيانات دخول خاطئة، رمز تجديد مُبطَل/منتهٍ |
| 403 | `FORBIDDEN` | لا صلاحية أو لا انتماء للمحل |
| 404 | `NOT_FOUND` | مسار/مورد غير موجود |
| 409 | `CONFLICT` | بريد أو هاتف مستخدم بالفعل |
| 429 | `TOO_MANY_REQUESTS` | تجاوز حد المحاولات على مسارات المصادقة |

## 4. الصلاحيات وعزل المحل

- `authenticate`: يستخرج ويؤكّد رمز الوصول؛ يضع `req.auth = { userId, role, jti }`.
- `requireShopMembership(userId, shopId)`: يتأكد أن المستخدم عضو **فعّال** في المحل، ويعيد عضويته (الدور + مفاتيح الصلاحيات). `shop_id` يُستخرج من عضوية المستخدم المؤكَّدة لا من الطلب (R-06).
- `hasPermission` / `requirePermission`: المالك (`owner`) يملك كل الصلاحيات؛ `staff` حسب مفاتيحه النصية (مثال `purchases.create`)؛ غير ذلك لا.
- الرسالة عند فشل الانتماء موحّدة كي لا تكشف وجود المحل من عدمه.

## 5. الإعدادات ذات الصلة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `JWT_ACCESS_SECRET` | — (إلزامي ≥32) | سر توقيع JWT |
| `ACCESS_TOKEN_TTL_SECONDS` | 900 | عمر رمز الوصول |
| `REFRESH_TOKEN_TTL_DAYS` | 30 | عمر رمز التجديد |
| `AUTH_RATE_LIMIT_MAX` | 20 | أقصى محاولات لكل دقيقة على مسارات المصادقة |
| `AUTH_RATE_LIMIT_WINDOW` | 60000 | نافذة حد المصادقة بالمللي ثانية |

## 6. خارج نطاق هذه المرحلة

- ربط المستخدم بمحل/إنشاء محل (المرحلة 5).
- ضبط/إعادة تعيين كلمة المرور عبر بريد/هاتف (يتطلب خدمة إرسال — لاحقًا).
- تطبيق التخزين الآمن للرموز في Flutter (`flutter_secure_storage`) — عند ربط التطبيق بالـ API (مرحلة لاحقة).

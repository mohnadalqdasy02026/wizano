## 1. أول تشغيل: حساب ← محل

```mermaid
flowchart TD
    A[تشغيل التطبيق] --> B{جلسة صالحة؟}
    B -- نعم --> K{متصل بالإنترنت؟}
    B -- لا --> C[إنشاء حساب / تسجيل الدخول]
    K -- نعم --> L{لديه محل؟}
    K -- لا وبلا جلسة --> C
    C --> E{قبول الخادم للحساب؟}
    E -- مرفوض --> C
    E -- مقبول --> L
    L -- نعم --> I[لوحة التحكم]
    L -- لا --> G[شاشة إعداد المحل: الاسم/العملة YER/المنطقة الزمنية]
    G --> I
```

**قاعدة:** لا يُسمح بالعمل دون اتصال قبل نجاح تسجيل الدخول الأولي وحفظ الجلسة.

## 2. تسجيل مشتريات — الوضع المتصل

```mermaid
flowchart TD
    A[شاشة المشتريات S13] --> B[اختيار العميل]
    B --> C[إدخال التفاصيل نصًا<br/>يدويًا أو عبر الميكروفون S14]
    C --> D[مراجعة النص وتعديله]
    D --> E[إدخال الإجمالي يدويًا]
    E --> F[إدخال المبلغ المدفوع يدويًا]
    F --> G{تحقق: إجمالي ≥ 0<br/>مدفوع ≥ 0<br/>مدفوع ≤ إجمالي؟}
    G -- لا --> F
    G -- نعم --> H[حساب المتبقي = إجمالي − مدفوع]
    H --> I[عرض الملخص وطلب التأكيد]
    I -- تأكيد المستخدم --> J[حفظ محليًا بمعرّف UUID فريد<br/>+ رقم عملية للمحل]
    J --> K[إرسال للخادم مع Idempotency-Key]
    K --> L{رد الخادم}
    L -- مقبول/معتمد --> M[S15 تفاصيل العملية<br/>حالة: معتمد مركزيًا]
    L -- مرفوض مع سبب --> N[عرض السبب + بقاء العملية محلية قابلة للتعديل]
    L -- انقطاع الاتصال --> O[حالة: محفوظ محليًا في طابور المزامنة]
```

**قواعد:**
- لا تحويل تلقائي من نص الأصناف إلى أسعار.
- لا تأكيد مالي دون تأكيد المستخدم صراحة.
- رقم العملية فريد **ضمن المحل**، والمعرّف فريد عالميًا.

## 3. تسجيل مشتريات — الوضع غير المتصل ثم المزامنة

```mermaid
flowchart TD
    A[لا اتصال] --> B[الحفظ في SQLite محليًا<br/>حالة: local_saved / queued]
    B --> C[عرض العملية للمستخدم بوسم<br/>«محلي — غير متزامن»]
    C --> D{عاد الاتصال؟}
    D -- لا --> C
    D -- نعم --> E[إرسال دفعة المزامنة بالترتيب<br/>مع مفاتيح idempotency ثابتة]
    E --> F{رد الخادم لكل عملية}
    F -- accepted --> G[تحديث الحالة: معتمد مركزيًا<br/>إخفاء الوسم المحلي]
    F -- rejected + سبب --> H[عرض السبب للمستخدم<br/>المعالجة يدوية]
    F -- conflict --> I[شاشة تعارض: عرض النسختين<br/>قرار المستخدم — دون خسارة بيانات]
    F -- فشل شبكي --> J[إعادة محاولة بأمان<br/>لا حذف من الطابور]
    G --> K[تسجيل النتيجة في sync_operations]
    H --> K
    I --> K
    J --> K
```

**ضمانات:** تكرار الإرسال لا يكرر العملية؛ العملية المكررة تعيد نفس النتيجة.

## 4. تسجيل دفعة

```mermaid
flowchart TD
    A[ملف العميل / S16] --> B[إدخال المبلغ + التاريخ + الطريقة]
    B --> C{تحقق: المبلغ أكبر من صفر ومنطقي؟}
    C -- لا --> B
    C -- نعم --> D[عرض: الرصيد قبل الدفعة<br/>والمتوقع بعد الدفعة]
    D --> E[تأكيد المستخدم]
    E --> F[قيد دفعة جديد مرتبط بالعميل والمحل]
    F --> G[قيد مستقل لا يعدّل قيمة المشتريات القديمة]
    G --> H[الرصيد بعد الدفعة = الرصيد قبل − المبلغ]
    H --> I[مزامنة (المتصل أو الطابور)]
```

## 5. حساب كشف الحساب والرصيد

```mermaid
flowchart TD
    A[S18 كشف حساب العميل] --> B[جلب العمليات المحسوبة من السجلات<br/>مشتريات + مدفوعات + مرتجعات + تصحيحات]
    B --> C[الترتيب الزمني]
    C --> D[حساب رصيد افتتاحي = 0]
    D --> E[لكل عملية بالترتيب:<br/>الرصيد بعد = الرصيد قبل + أثر العملية]
    E --> F[عرض الرصيد بعد كل عملية]
    F --> G{تطابق الرصيد النهائي<br/>مع القيمة المخزنة؟}
    G -- لا --> H[تنبيه تدقيق داخلي + تسجيل الخطأ]
    G -- نعم --> I[عرض كشف الحساب]
```

**أثر العملية على الرصيد:**

| النوع | الأثر |
|---|---|
| مشتريات | + الإجمالي |
| دفعة | − المبلغ |
| مرتجع | − المبلغ |
| تصحيح موجب | + المبلغ |
| تصحيح سالب | − المبلغ |
| إلغاء عملية | − أثر تلك العملية |

## 6. مرتجع / تصحيح / إلغاء (مع تدقيق)

```mermaid
flowchart TD
    A[S19 تفاصيل عملية] --> B{الإجراء}
    B -- مرتجع --> C[S20: اختيار العملية + مبلغ المرتجع]
    B -- تصحيح --> D[S21: مبلغ + سبب إلزامي]
    B -- إلغاء --> E[S22: سبب الإلغاء]
    C --> F{تحقق القيم}
    D --> F
    E --> F
    F -- غير صالح --> B
    F -- صالح --> G[عرض الأثر على الرصيد + التأكيد]
    G --> H[إنشاء قيد جديد مرتبط بالأصل]
    H --> I[الأصل يبقى كما هو — لا حذف ولا تعديل صامت]
    I --> J[audit_logs: المستخدم/الوقت/السبب/قبل-بعد]
    J --> K[مزامنة + اعتماد مركزي]
```

## 7. اعتراض العميل ومعالجته

```mermaid
flowchart TD
    A[تطبيق العميل: تفاصيل عملية] --> B[إرسال اعتراض + نص السبب]
    B --> C[حالة الاعتراض: مفتوح]
    C --> D[إشعار داخل التطبيق لصاحب المحل S24]
    D --> E[صاحب المحل يفتح S25 ويرد]
    E --> F[رد موثق + تحديث الحالة]
    F --> G[إشعار للعميل في C07]
    G --> H{مغلق أو قيد المراجعة؟}
    H -- قيد المراجعة --> E
    H -- مغلق --> I[يبقى في السجل للتدقيق]
```

**قاعدة:** الاعتراض لا يغيّر أرقامًا مالية تلقائيًا؛ أي تعديل مالي نتيجة اعتراض = إجراء تصحيح مستقل موثق بموافقة المالك.

## 9. ملخص نقاط الاتصال بين المكونات

| المسار | المتجه | الغرض |
|---|---|---|
| `POST /api/v1/auth/*` | التطبيقان ← الخادم | تسجيل/دخول/تجديد/خروج |
| `POST/GET /api/v1/shops*` | صاحب المحل ← الخادم | الملف والإعدادات |
| `GET/POST/PATCH /api/v1/customers*` | صاحب المحل ← الخادم | العملاء والربط |
| `POST/GET /api/v1/purchases*` | صاحب المحل ← الخادم | المشتريات (مع Idempotency-Key) |
| `POST/GET /api/v1/payments*` | صاحب المحل ← الخادم | المدفوعات |
| `POST /api/v1/returns` و`adjustments` و`cancellations` | صاحب المحل ← الخادم | القيود المصححة |
| `GET /api/v1/statements/:customerId` | كلا التطبيقين ← الخادم | كشف الحساب |
| `POST/GET /api/v1/objections*` | العميل ← الخادم | الاعتراضات والردود |
| `GET /api/v1/sync/push` و`pull` | تطبيق صاحب المحل ← الخادم | المزامنة |
| `GET /api/v1/notifications` | كلا التطبيقين ← الخادم | الإشعارات الداخلية |
| `GET /api/v1/reports/*` | صاحب المحل ← الخادم | التقارير |

> أسماء المسارات تقريبية وتُثبَّت في المرحلة 2/4 مع توثيق OpenAPI عند الحاجة.

## 1. استراتيجية الاختبار

| الطبقة | الأداة | نطاقها |
|---|---|---|
| اختبارات وحدة (قواعد مالية) | `flutter_test` + Vitest | حساب المتبقي، الرصيد، القيود، التحقق من المدخلات |
| اختبارات تكامل (API + DB) | Vitest + supertest + PostgreSQL | المصادقة، الصلاحيات، العزل، idempotency، الترحيلات |
| اختبارات واجهة | `flutter_test` (widget tests) | حالات التحميل/الفراغ/الخطأ، RTL، التنقل |
| اختبارات سيناريو (عمل دون اتصال) | تكامل + اختبارات يدوية على جهاز | الطابور، إعادة الإرسال، التعارض، إعادة التشغيل |
| فحص ثابت | `flutter analyze` + `tsc --noEmit` | نظافة الكود |
| يدوي E2E | قائمة تحقق لكل مرحلة | المسارات المالية الكاملة على جهاز فعلي |

**قواعد عامة:**

- لا تُعلَّن مرحلة مكتملة وعليها أخطاء حرجة أو وظيفة أساسية لا تعمل.
- لا تُستخدم بيانات وهمية لإخفاء نقص وظيفي.
- كل رقم مالي في اختبار له توقع محسوب يدويًا موثّقًا في الاختبار نفسه.
- بيانات الاختبار (seeds) لا تُنقل إلى الإنتاج أبدًا.
- لا يُنشئ مطور (أنا) بيانات إنتاجية حقيقية لحسابات مستخدمين دون موافقة.

## 2. مناطق الاختبار الأساسية

### 2.1 القواعد المالية (الأولوية القصوى)

| الاختبار | التوقع |
|---|---|
| إجمالي 10,000 − مدفوع 3,000 | متبقي 7,000 |
| مدفوع = إجمالي | متبقي 0 |
| مدفوع > إجمالي | رفض + رسالة تحقق، بلا حفظ |
| قيم سالبة (إجمالي أو مدفوع) | رفض + رسالة تحقق |
| إجمالي 0 ومدفوع 0 | مرفوض أو مقبول بقرار موثق (يُحسم في المرحلة 8) |
| رصيد بعد سلسلة: شراء 10,000، دفعة 3,000، مرتجع 1,000، تصحيح −500 | الرصيد = 5,500 يدويًا مقابل الحساب |
| إعادة حساب كشف الحساب | القيمة المشتقة = القيمة المخزنة دائمًا (صفر تفاوت) |
| إلغاء عملية | الرصيد يعود للحالة قبلها تمامًا |
| دفعة جديدة | لا تغيّر قيم المشتريات القديمة إطلاقًا |

### 2.2 الخادم

| المنطقة | يُختبر |
|---|---|
| المصادقة | تسجيل، دخول، خروج، انتهاء الرمز، تجديد بتدوير، رفض رمز مزوَّر |
| الصلاحيات | كل دور يُمنع من ما ليس له (403) مهما كان الواجهة |
| العزل | محل لا يرى عملاء/عمليات محل آخر في أي مسار |
| idempotency | نفس الطلب 5 مرات = عملية واحدة فقط |
| التحقق | كل مدخل خاطئ = 400 برسالة عربية واضحة |
| الترحيلات | تنظيف من الصفر + رفع على قاعدة موجودة دون فقدان |
| الأسرار | لا كلمة مرور أو رمز في أي سجل/استجابة |

### 2.3 دون اتصال والمزامنة (مراحل 13-14)

| السيناريو | التوقع |
|---|---|
| حفظ عملية ثم إغلاق التطبيق وفتحه | العملية موجودة بحالتها |
| إطفاء الشبكة ثم إدخال 3 عمليات ثم التشغيل | الطابور يحفظها كلها بترتيبها |
| عودة الاتصال | كلها تُرسل وتُعتمد مرة واحدة |
| إعادة إرسال نفس الدفعة | لا تكرار مالي |
| انقطاع أثناء الإرسال | لا فقدان ولا حالة معلقة بلا سبب |
| تعارض تعديل | `conflict` مع عرض النسختين، لا دمج صامت |
| محلي غير معتمد | وسمه لا يشبه وسم «معتمد» |

### 2.4 الواجهة

- RTL كامل (بداية/نهاية المنطقية معكوستان).
- 3 أحجام شاشات على الأقل (صغيرة 5"، متوسطة، كبيرة).
- حالات التحميل/الفراغ/الخطأ لكل قائمة.
- أزرار بلا وظيفة = عيب.

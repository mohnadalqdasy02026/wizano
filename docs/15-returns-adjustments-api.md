## 1. المفهوم

المرحلة 11 تضيف **القواعد المالية التصحيحية** على رصيد العميل، مع إبقاء الأصل المالي سليمًا:

| الإجراء | الطبيعة المحاسبية | الأثر على الرصيد |
|---|---|---|
| **مرتجع** (`purchase_returns`) | قيد جديد مرتبط بالعملية الأصلية | `− المبلغ` |
| **تصحيح مالي** (`financial_adjustments` kind=`correction`) | قيد موجب أو سالب + **سبب إلزامي** | `± المبلغ` |
| **إلغاء عملية** (`financial_adjustments` kind=`cancellation`) | **قيد عكسي** بقيمة صافي أثر العملية المتبقي | `− صافي الأثر المتبقي` |

**صيغة الرصيد الموحّدة (تُطبَّق في كل الوحدات عبر `common/balance.ts`):**

```
رصيد العميل = Σ المشتريات (النشطة)
            − Σ المدفوعات
            − Σ المرتجعات
            ± Σ التصحيحات المالية
```

- **لا حذف ولا تعديل صامت:** العملية الأصلية تبقى `active` بقيمتها؛ الإلغاء مجرد **قيد عكسي** منفصل،
  فيظهر في الكشف كسطر مستقل (docs/01 §4.3، D-11).
- **قابلية التحقق:** حساب الرصيد موحّد في وحدة واحدة (`computeCustomerBalance` / `customerBalanceBreakdown`)
  تستدعيها المشتريات والمدفوعات والمرتجعات والتصحيحات وكشف الحساب — فلا تتباعد الصيغ.

## 2. المسارات

جميعها تتطلب `Authorization: Bearer <access>` + انتماء فعّال للمحل (`requireShopMembership`).

### 2.1 المرتجعات

| الطريقة | المسار | الحالة | الوصف |
|---|---|---|---|
| GET | `/api/v1/shops/:shopId/returns` | 200 | قائمة مرتجعات المحل (تصفية `?customerId=`) |
| POST | `/api/v1/shops/:shopId/returns` | 201 | تسجيل مرتجع مرتبط بعملية |
| GET | `/api/v1/shops/:shopId/returns/:returnId` | 200 | تفاصيل مرتجع |

**جسم POST:**

```jsonc
{
  "id": "uuid-v7-اختياري",        // معرّف مفروض من العميل (منع التكرار في المزامنة)
  "purchaseId": "uuid",           // العملية الأصلية — إلزامية
  "amount": 2000,                 // > 0
  "reason": "بضاعة تالفة",        // اختياري
  "occurredAt": "2026-10-21T00:00:00.000Z"  // اختياري
}
```

**الاستجابة:** كائن المرتجع مع `balanceAfter` (الرصيد المشتق بعد القيد).

### 2.2 التصحيحات المالية

| الطريقة | المسار | الحالة | الوصف |
|---|---|---|---|
| GET | `/api/v1/shops/:shopId/adjustments` | 200 | قائمة التصحيحات/الإلغاءات (تصفية `?customerId=`) |
| POST | `/api/v1/shops/:shopId/adjustments` | 201 | تسجيل تصحيح مالي |
| GET | `/api/v1/shops/:shopId/adjustments/:adjustmentId` | 200 | تفاصيل تصحيح |

**جسم POST:**

```jsonc
{
  "id": "uuid-v7-اختياري",
  "customerId": "uuid",           // إلزامي
  "relatedPurchaseId": "uuid",    // اختياري (ربط توثيقي بعملية)
  "amount": -1200,                // ≠ 0 (موجب يزيد، سالب يخصم)
  "reason": "خصم إداري",          // إلزامي
  "occurredAt": "…"               // اختياري
}
```

### 2.3 إلغاء عملية

| الطريقة | المسار | الحالة | الوصف |
|---|---|---|---|
| POST | `/api/v1/shops/:shopId/purchases/:purchaseId/cancel` | 201 | إلغاء بقيد عكسي |

**جسم POST:**

```jsonc
{ "id": "uuid-v7-اختياري", "reason": "عملية مكررة", "occurredAt": "…" }
```

**الاستجابة:** قيد `financial_adjustments` مع `kind: "cancellation"`,
`amount = −(إجمالي العملية − مدفوعاتها − مرتجعاتها)` و`balanceAfter`.

### 2.4 سجل التدقيق

| الطريقة | المسار | الحالة | الوصف |
|---|---|---|---|
| GET | `/api/v1/shops/:shopId/audit-logs` | 200 | إجراءات المحل المالية (الأحدث أولًا) |

**معلّمات اختيارية:** `entityType`, `entityId`, `action`, `limit` (افتراضي 100، أقصى 200).

**الاستجابة:** عناصر بكل من `action`, `entityType`, `entityId`, `before`, `after`, `createdAt`.

## 3. قواعد

### 3.1 التحقق من المبلغ (D-25)

- **مرتجع:** لا يتجاوز **متبقي العملية** = `الإجمالي − مدفوعاتها − مرتجعاتها السابقة`؛ وإلا 400.
- **تصحيح سالب:** لا يجعل رصيد العميل سالبًا (`−amount ≤ الرصيد الحالي`)؛ وإلا 400.
- **تصحيح:** لا يكون صفريًا، وسببه **إلزامي**.
- **إلغاء:** لا يوجد **رصيد متبقٍ لعكسه** (= 0) ⇒ 400 (لا شيء لإلغائه).

### 3.2 منع الازدواج

- **إلغاء مزدوج:** وجود قيد `cancellation` سابق لنفس العملية ⇒ 400.
- **مرتجع على عملية ملغاة:** وجود قيد `cancellation` للعملية ⇒ 400 (منع الخصم المزدوج).
- **Idempotency-Key** (ترويسة): إعادة الإرسال بنفس المفتاح تُعيد الكيان القائم بدل إنشاء نسخة (R-07).
- **معرّف من العميل** (UUIDv7): إن وُجد مسبقًا يُعاد بدل التكرار (R-04).

### 3.3 العزل والتدقيق

- **العزل:** عدم الانتماء ⇒ 403؛ عميل غير مرتبط ⇒ 404؛ مرتجع/تصحيح لمحل آخر ⇒ 404.
- **سجل التدقيق:** كل إجراء يُكتب في `audit_logs` (غير قابل للتعديل/الحذف عبر trigger في القاعدة)
  مع الفاعل والطابع الزمني والسبب والأثر.
- **الذرّية:** كل إجراء يُنفَّذ ضمن **معاملة واحدة** (إدراج القيد + حساب `balanceAfter` + سجل التدقيق).

### 3.4 أثر الإجراءات على كشف الحساب

بعد توسيع وحدة `statements`، تتضمن أسطر الكشف الأنواع: `purchase | payment | return | adjustment`،
مع `adjustmentKind` لأسطر التصحيحات. الرصيد الجاري `balanceAfter` يتراكم عبر الأنواع الأربعة جميعًا،
والإجماليات الجديدة: `totalReturns`, `totalAdjustments` (بلا تصفية).

## 4. الأخطاء

| الحالة | الكود | متى |
|---|---|---|
| 400 | `BAD_REQUEST` | تجاوز المتبقي، تصحيح سالب > الرصيد، سبب ناقص، مبلغ صفر، إلغاء مزدوج، لا رصيد متبقٍ للإلغاء |
| 401 | `UNAUTHORIZED` | لا رمز مصادقة |
| 403 | `FORBIDDEN` | لا انتماء للمحل |
| 404 | `NOT_FOUND` | عملية/عميل/مرتجع/تصحيح غير موجود أو خارج المحل |

## 5. تطبيق صاحب المحل

- **S20** تسجيل مرتجع: يُفتح من S19 (عملية شراء نشطة) — المبلغ + السبب الاختياري، مع عرض المتبقي.
- **S21** تصحيح مالي: من S18 (أيقونة) أو S19 — مبلع موقّع (زيادة/خصم) + **سبب إلزامي**.
- **S22** إلغاء عملية: من S19 (عملية شراء نشطة) — يوضّح القيد العكسي ويطلب السبب.
- **S23** سجل التدقيق: من S18 (أيقونة) — يسرد الإجراءات مع السبب والأثر على الرصيد.
- كشف الحساب (S18) يعرض الآن 4 إجماليات (مشتريات/مدفوعات/مرتجعات/صافي تصحيحات) + شرائح تصفية
  موسّعة (مرتجعات/تصحيحات) + أسطر ملوّنة حسب النوع.

## 1. المفهوم

- **كشف الحساب** عرض تجميعي — وليس مخزنًا جديدًا — يجمع عمليات العميل (**المشتريات + المدفوعات**)
  في تسلسل زمني مع **الرصيد الجاري بعد كل عملية** (docs/01 §4.2، docs/03 §5).
- **الرصيد مشتق من السجلات المالية فقط** ولا يُعدَّل يدويًا:
  `الرصيد = Σ المشتريات (النشطة) − Σ المدفوعات` (D-09).
- **أثر العملية على الرصيد:** مشتريات `+ الإجمالي`، دفعة `− المبلغ`.
  (المرتجعات `−`، التصحيحات `+/−`، الإلغاء `−` تُضاف في المرحلة 11.)
- **الترتيب:** زمني تصاعدي حسب `occurred_at`/`paid_at`، وعند التساوي تُرتَّب المشتريات قبل الدفعات.
- **التصفية** (نوع/نطاق تاريخ) تؤثر على **العرض فقط**؛ الرصيد الجاري يبدأ من صافي ما قبل نقطة البداية،
  فيبقى رصيد آخر عملية مطابقًا للرصيد الحقيقي للعميل بغض النظر عن التصفية.

## 2. المسار

يتطلب `Authorization: Bearer <access>` + انتماء فعّال للمحل (`requireShopMembership`).

| الطريقة | المسار | الحالة | الوصف |
|---|---|---|---|
| GET | `/api/v1/shops/:shopId/customers/:customerId/statement` | 200 | كشف حساب العميل (زمنيًا + الرصيد الجاري) |

**معلّمات الاستعلام (اختيارية):**

| البارامتر | القيم | الوصف |
|---|---|---|
| `type` | `all` (افتراضي) \| `purchase` \| `payment` | تصفية نوع العملية |
| `from` | ISO datetime | بداية النطاق (شامل) |
| `to` | ISO datetime | نهاية النطاق (شامل) |

**الاستجابة:**

```jsonc
{ "data": {
  "customerId": "uuid",
  "totalPurchases": "15000",   // Σ المشتريات النشطة (بلا تصفية)
  "totalPayments": "6500",     // Σ المدفوعات (بلا تصفية)
  "balance": "8500",           // الرصيد الحالي = totalPurchases − totalPayments
  "entries": [
    { "id": "uuid", "type": "purchase", "shopSeq": "1",
      "occurredAt": "2026-10-20T22:01:33.936Z", "description": "Rice10kg",
      "effect": "10000", "balanceAfter": "10000", "status": "active",
      "purchaseId": null },
    { "id": "uuid", "type": "payment", "shopSeq": "1",
      "occurredAt": "2026-10-20T22:01:33.936Z", "description": "دفعة وقت الشراء",
      "effect": "-3000", "balanceAfter": "7000", "status": "active",
      "purchaseId": "uuid-العملية-المرتبطة" }
  ]
} }
```

> **ملاحظة:** المبالغ والأرصدة تُعاد كسلاسل نصية (bigint) لتجنّب فقدان الدقة في JavaScript.

## 3. قواعد

- **العزل:** عدم الانتماء للمحل ⇒ 403؛ عميل غير مرتبط بالمحل ⇒ 404 (لا نكشف وجوده).
- **الإجماليات** (`totalPurchases`/`totalPayments`/`balance`) تُحسب على كامل تاريخ العميل
  **بلا تصفية**، لتبقى متسقة مع الرصيد المخزَّن على صفوف العمليات (`balance_after`).
- **الرصيد الجاري** لكل سطر (`balanceAfter`) يتراكم عبر كل العمليات حتى تلك اللحظة،
  بما يشمل ما قبل نطاق التصفية — فلا يبدأ الحساب من الصفر عند التصفية.
- **الدفعات المرتبطة** بعملية شراء تظهر كسطر مستقل (`type: payment`, `purchaseId` مضبوط)
  مع بيان «دفعة وقت الشراء» الذي يسجّله خادم المشتريات.
- الرصيد النهائي في الكشف يجب أن يطابق `balance_after` المخزَّن على أحدث عملية (تدقيق §4.2).

## 4. الأخطاء

| الحالة | الكود | متى |
|---|---|---|
| 400 | `BAD_REQUEST` | فشل التحقق (نطاق تاريخ غير صالح، نوع غير معروف) |
| 401 | `UNAUTHORIZED` | لا رمز مصادقة |
| 403 | `FORBIDDEN` | لا انتماء للمحل |
| 404 | `NOT_FOUND` | العميل غير مرتبط بالمحل |

## 5. تطبيق صاحب المحل

- **S18** كشف حساب العميل: ترويسة بالإجماليات + الرصيد، شرائح تصفية (الكل/مشتريات/مدفوعات)،
  قائمة زمنية بالرصيد الجاري، تُفتح من زر «كشف الحساب» في ملف العميل (S11).
- **S19** تفاصيل أي عملية: النوع، الرقم، التاريخ، البيان، المصدر، الحالة، الأثر على الرصيد،
  والرصيد بعد العملية.
